# AI にレトロゲームをやらせる動画企画 — 法務・技術 検討メモ

調査日: 2026-09-21

> **免責**: 筆者は弁護士ではない。以下は公開情報にもとづく整理であり、法的助言ではない。
> とくに法人として実施する場合は、著作権に強い弁護士への確認と、任天堂への直接照会を推奨する。

---

## 1. 結論（先に）

| 案 | 法務リスク | 技術難度 | 判定 |
| --- | --- | --- | --- |
| エミュレータ + ポケモン ROM + YouTube | **高**（任天堂ガイドライン明文違反） | 低 | ✕ |
| Switch 実機 + キャプチャ + マイコン入力 | 中（法人問題のみ残る） | 中 | ◎ 本命 |
| 配信ガイドライン整備済みの PC 復刻版 | 低 | 低 | ○ |
| homebrew / 自作レトロゲーム | ほぼ無し | 低 | ○（企画の新規性も高い） |

ポイントは 2 つ。

1. **エミュレータは 2024-09-02 のガイドライン更新で明示的に許諾対象外になった。** 正規カートリッジを
   所有していても、エミュレータでプレイした映像の公開は許諾の外に出る。
2. **任天堂のガイドラインは「個人」限定。** 法人・団体が業務として行う投稿は対象外。
   moshimo-hack の事業としてやるなら、個別許諾が別途必要。

## 2. 法務面の整理

権利の問題は 4 層に分かれる。どれか 1 つでも欠けるとアウトになる。

### レイヤー 1 — エミュレータソフト本体

エミュレータソフトを動かすこと自体を直接禁じる日本の法律はない。ただし任天堂は近年きわめて
強硬で、Switch エミュレータについては

- **Yuzu**: 2024-02-26 に任天堂が提訴 → 2024-03-04 に 240 万ドルで和解、開発停止・全コピー破棄
- **Ryujinx**: 2024-10 に非公開合意で停止、GitHub リポジトリ消滅
- 2025〜2026 にかけて Sudachi / Suyu / Citron / MeloNX などフォーク群へ DMCA を大量送付

和解で終わっているため判例としての先例価値はないが、任天堂の姿勢は明確。

### レイヤー 2 — ROM の入手

**ネットからのダウンロード → 明確に違法。**
2021-01-01 施行の改正著作権法で、それまで音楽・映像に限られていた違法ダウンロード規制が
著作物全般（プログラムを含む）に拡大された。罰則は 2 年以下の懲役もしくは 200 万円以下の罰金
（またはこれを併科）。ただし音楽・映像以外は「継続的にまたは反復して」行うことが刑事罰の要件。

**自分のカートリッジからの吸い出し → 条件付きで私的複製（著作権法 30 条）の余地あり。** ただし

- 技術的保護手段（コピーガード）を回避する場合は 30 条 1 項 2 号により私的複製の例外から外れる
- 吸い出し後に元のソフトを売却・譲渡すると、手元のコピーが違法複製物扱いになる
- 吸い出し機器の販売側は不正競争防止法の問題になりうる（いわゆるマジコン事件の系譜）
- **そして最大の落とし穴 → 30 条はあくまで「私的使用」の話。**
  YouTube へのアップロードは公衆送信であり、私的複製の枠を完全に外れる。
  「正規に買ったカートリッジを自分で吸い出したから大丈夫」は、動画公開の場面では成立しない。

### レイヤー 3 — 実況動画としての公開 ← 本丸

ゲーム実況は本来、複製権・翻案権・公衆送信権・同一性保持権に触れうる行為で、権利者の許諾が
あって初めて成り立つ。任天堂は「ネットワークサービスにおける任天堂の著作物の利用に関する
ガイドライン」で、条件を満たす個人に対して著作権侵害を主張しない、という形の許諾を出している。

**2024-09-02 の更新で、違法または不適切な投稿として次が明記された:**

> エミュレーターや技術的制限手段を回避するプログラムなど、不正行為からゲームソフトやゲーム機を
> 保護するために任天堂が導入したセキュリティを回避するソフトウェアや装置の使い方に関するもの

あわせてチート・クラッキングを可能にするもの、データマイニングで抽出した通常プレイでは
見られない画像なども禁止に追加。さらにガイドラインに従わない投稿には

- 法的措置を講じる権利を保持
- 以後の任天堂のゲーム著作物の使用を認めない権利を保持

と追記された。つまり **エミュレータ映像 = 許諾対象外 = 無許諾の公衆送信** という整理になる。

### レイヤー 4 — 法人かどうか ← 見落とされがちで、実は一番重い

ガイドラインの対象は **個人の投稿に限られる**。投稿者が団体・法人に所属し、団体の業務として
行う投稿にはガイドラインは適用されない。

過去に UUUM、ソニー・ミュージックマーケティング、東京産業新聞社、いちから（現 ANYCOLOR）などが
任天堂と個別の許諾契約を締結している。逆に言えば、**契約のない法人は個人向けガイドラインに
乗れない**。

「個人アカウントの体裁でやる」としても、会社の業務として企画・制作・運用している実態があれば
そこで判断されるリスクがある。ここは事前に任天堂へ照会するのが確実。

### ポケモン固有の事情

- 権利は任天堂・クリーチャーズ・ゲームフリークの共有で、株式会社ポケモンが管理
- 株式会社ポケモンは **本編シリーズについて独自の実況ガイドラインを公開していない**
  （『ポケモンユナイト』『Pokémon Champions』には個別ガイドラインあり）
- 実務上は任天堂ガイドラインに従うのが通例だが、明文の許諾がない分グレーが残る

## 3. 現実的な代替案

### 案 A（本命）— Switch 実機 + キャプチャ + マイコン入力

2026-02-27、ポケモン 30 周年にあわせて **Switch 版『ポケットモンスター ファイアレッド・
リーフグリーン』が各 2,000 円で配信開始**。正規に購入できる現行商品がある。

構成:

```
Switch 実機 ──HDMI──> キャプチャデバイス ──USB──> PC（画面取得）
                                                    │
                                                    ↓ Claude API
                                                    │
Switch 実機 <──USB/BT── Raspberry Pi Pico / ESP32 <─┘（コントローラーとして入力注入）
```

- ROM も、エミュレータも、技術的保護手段の回避も **一切発生しない**
- ガイドラインのエミュレータ条項に引っかからない
- 既存 OSS が豊富: Poke-Controller（LUFA/AVR + シリアル + キャプチャ）、NXBT（Raspberry Pi で
  コントローラーエミュレーション）、SwitchControllerPico、Pokémon Automation
- 遅延はキャプチャ経由で 0.1〜0.2 秒程度。ターン制 RPG なら全く問題にならない

残る論点:

- **法人問題は未解決**。ここだけは任天堂への照会が必要
- 自動化ツールはオンライン対戦では利用規約上 NG。**オンライン要素に触れない設計**にする

### 案 B — 配信ガイドライン整備済みの PC 復刻版

セガ、カプコン、コナミ、タイトーなどは復刻コレクションを Steam 等で販売し、配信ガイドラインも
整備している（法人可のケースもある）。PC 上で動くので画面キャプチャ + キー入力注入が最も簡単。
エミュレータ問題も法人問題も、タイトル選定次第でクリアできる。

### 案 C — homebrew / 自作レトロゲーム

itch.io の Game Boy Homebrew コレクション、GB Studio 製の同人 GB ソフトなど。作者に許諾を取れば
完全にクリーン。**「AI に無名の自作ゲームを初見でやらせる」は企画としてもむしろ新鮮**で、
攻略情報が学習データに入っていない = 本当の初見プレイになるという利点もある。

### 案 D — 自社で権利を持つ

レトロ風ゲームを自作して AI にプレイさせる。既存の `pokemon-voice-quiz/` の延長線上。

## 4. 技術面 — AI にゲーム画面を見せてプレイさせられるか

### 結論: できる。すでに実証済み。

- **2025-02** Anthropic が Twitch で `ClaudePlaysPokemon` を開始。Claude 3.7 Sonnet がポケモンレッドを
  プレイ。初期ハーネスはスクリーンショット + 仮想ボタン入力 + ノート（知識ベース）+
  パスファインディングツール + **ゲーム RAM からの現在地・パーティ情報の読み出し**（画面誤読の補正用）
- それでも 3.7 Sonnet はお月見山で何十時間も停滞
- **2025-05** Gemini 2.5 Pro がポケモンブルーをクリア
- **2026-05** Claude Opus 4.7 がポケモンレッドをクリア
- **2026-06** Claude Fable 5 が **生のスクリーンショットのみ**（マップなし・RAM アクセスなし・
  ナビゲーションハーネスなし）でファイアレッドを最初から最後までクリア。Anthropic が
  タイムラプス動画を公開。戦略はヒトカゲ → リザードンを Lv78 まで育てて四天王を力押し
- NeurIPS 2025 の PokeAgent Challenge という公式ベンチマークも存在。最良のエージェントでも
  人間のスピードランナーの 2.2 倍遅い

### 「何の説明もなしに」はどこまで本当か

正直に言うと、ここは 2 つに分けて考える必要がある。

**成立する部分:**
ボタン割り当てを教えなくても、画面を見て「A が決定らしい」と推論し、試行錯誤で学習することは
可能。攻略情報やマップを与えなくてもクリアできることは Fable 5 が実証した。最低限必要な「説明」は
実質、入力インターフェースの定義だけ。

**成立しない部分:**
Claude はポケモン赤/緑/FRLG の知識を学習データとして持っている。**「完全な初見・ゼロ知識」ではない。**
番組の建て付けとして「AI の初見プレイ」を強く謳うと、そこは誇張になる。
本当の初見をやりたいなら案 C（無名の homebrew）が正解。

### 必要なハーネス（4 要素）

1. **画面取得** — エミュレータのフレームバッファ、またはキャプチャデバイスから PNG
2. **推論** — Claude API（Messages API + vision）に画像 + 文脈を投げる
3. **入力注入** — 返ってきた行動（例: `["UP","UP","A"]`）をパースしてボタン入力に変換
4. **長期記憶 + ループ制御** — ノートファイル、定期要約、直近 N フレームの履歴

実装の選択肢:

| 対象 | 推奨 |
| --- | --- |
| Game Boy | PyBoy（Python ネイティブ、`screen.ndarray` でフレームバッファ直取り） |
| GBA | mGBA の Python バインディング、または Lua ソケットブリッジ |
| Switch 実機 | キャプチャデバイス + Raspberry Pi Pico / ESP32 |

### 実運用のボトルネック（= 企画設計に直結する）

- **コスト**: スクリーンショット 1 枚で約 1,600 トークン。1 アクションごとに画像を投げると、
  数千〜数万ステップかかるゲームでは費用が積み上がる。→ 複数フレームの間引き、解像度の調整、
  プロンプトキャッシュで圧縮する
- **速度**: 1 アクションあたり数秒。**リアルタイムのアクションゲームは無理。**
  ターン制 RPG・パズル・アドベンチャーが向く。ポケモンが題材に選ばれ続けているのはこれが理由
- **コンテキスト**: 数千ステップ回すと履歴が溢れる。定期要約とノートファイルへの外部化が必須
- **低解像度ドット絵の読み取り**: GB は 160x144。拡大（ニアレストネイバー）やグリッド線の
  重ね描きといった前処理が効く
- **空間認識**: 歴代の詰まりポイントはほぼこれ（迷路、マップの繋がり）。
  ただし **ここが動画としては一番の見せ場**でもある

## 5. 動画企画としての所見

- 実時間をそのまま流すのは退屈。**倍速タイムラプス + 要所の思考ログ字幕**が鉄板
- **Claude の「思考」をそのまま字幕に出すのが最大の差別化。**
  人間の実況者にはない「なぜその操作をしたのか」が全部見える
- 伸びる構成は「AI が詰まる → 変な仮説を立てる → たまたま抜ける」の三幕
- ただし `ClaudePlaysPokemon` が Twitch で 1 年以上走り、Anthropic 自身がタイムラプスを
  公開している以上、**ポケモン × AI はすでに激戦区**。案 C の「無名の homebrew に初見で挑ませる」
  ほうが、新規性でも法務でも優位に立てる可能性がある
